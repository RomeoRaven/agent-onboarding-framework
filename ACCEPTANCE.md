# Manual onboarding acceptance

Keep a compact outcome record with the destination's owner. Do not put local facts, refusals, task transcripts, or private source inventories in the generic repository. If a check fails, correct its owning source and repeat the affected checks before consequential work.

1. Bootstrap: a fresh human finds the local manifest from the destination's existing startup entrypoint without prior conversation, obtains access to each required source, and can explain where private answers belong. Note any access blocker.
2. Loaded set: record each required framework, personal, system, and source file (plus role/project files when declared), its exact location, verified revision or stable version, and who owns it. Confirm that no required source is missing, duplicated, or unverified and no copied template comments/placeholders remain.
3. Authority: the agent explains personal, destination, and project owners; how to resolve a conflict; and why Markdown order cannot grant permission.
4. Source lookup: successfully open one canonical source declared in `SOURCES.md` using its authorized access route.
5. Boundary: present one deliberately out-of-authority request without carrying it out. Record the refusal and the correct owner/approval route; do not test with a harmful live action.
6. Capability: complete one small, realistic, authorized task, with a readback or observable result in its owner surface.
7. Disclosure: review both prospective package contents and any staged changes before the first commit. The generic history must have no personal/local material; the private profile must have no secrets, exact host routes, volatile state, sessions, or raw memory. If material was distributed, assess exposure; a history rewrite cannot recall copies.
8. Portability: a meaningfully different agent/harness or human-led path follows these instructions without modifying generic files. Record what worked or where adaptation was required at the destination.
9. Permission reality: confirm the destination's actual filesystem, credential, publishing, and service controls independently of document claims.

Accept only if required checks pass, or explicitly keep onboarding unaccepted with the failing check, owner, and next safe route recorded locally. This is manual evidence, not an automated compliance certificate.
